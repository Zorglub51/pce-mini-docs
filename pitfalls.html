Pitfalls & Gotchas

Configuration mistakes, their actual causes, and the limits of what a symptom proves.

1. Sort Ranks Must Describe the Active Lineup

For each active lineup of N entries, each of sor_name, sor_date, sor_genr and sor_pnum should contain every rank from 0 to N−1 once. The menu inverts these ranks into s_indextable[rank] = item. Duplicate ranks overwrite an entry and leave holes. Keeping ranks from a larger original lineup can leave active positions mapped to the sentinel LINEUPMAX=50.

The stock index array has 60 entries, not N. A rank greater than N−1 is therefore not necessarily an immediate array-bounds error, but it still breaks the intended permutation. There is no evidence that Squirrel silently corrupts memory on such an access. A black menu is a symptom to investigate, not proof of VM corruption. sor_demo has a separate role in the demonstration build; it is not the retail attract-mode playback order. 

# A simple valid order; apply only to active items in each section.
for i, item in enumerate(active_items):
    for key in ('sor_name', 'sor_date', 'sor_genr', 'sor_pnum'):
        item[key] = i

See title_mode_top before changing the count or sorting.

2. Keep the Profile's root Wrapper and Real Field Names

Stock game_content.nut:_get_title_prof() accesses util_load_config(path).root, then merges title_prof_specdepend. A flat profile is incompatible with that reader. This requirement comes from Squirrel; it is not a special native title_prof parser rejecting unfamiliar keys. 

{
  "root": {
    "m2epi": { "version": { "GAME000": {
      "arch": "tg16", "country": "jp", "rom": "roms/MyGame.pce"
    } } },
    "player_num": 6
  }
}

This fragment illustrates nesting, not a complete launchable package. Shared controller, wallpaper, replay and version metadata have their own readers and requirements. There is no established rule that exactly seven sections are mandatory or that unknown keys themselves crash the native loader.

Use the actual names replay.init_replay_record_time, replay.max_replay_record_time, replay.replay_record_time_list, wallpaper.datafile and wallpaper.max_num. Names such as replay.fps or wallpaper.motion_file do not substitute for them. Replay record-time values are in minutes. See the profile reference for defaults and conditional readers.

3. MZS Uses the Full Basename

Key derivation includes the lowercased filename including its extensions: title_prof.psb.m, not just title_prof. Renaming an encrypted file changes the expected key. Repack with the intended destination basename if you need a new name. Moving it to another directory without changing that basename does not change this filename-derived key.

A failed zstd decode can also mean a wrong game key, damaged payload or wrong format; it does not uniquely identify a rename. See MZS / PSB Format.

4. Padding Slots Are Not Active Games

The examined menu contains 200 items in four sections of 50. Counts titleNum and titleNumTG determine which entries are active. Stock padding entries use regionTag="DUMMY", players=1 and demo_time=6180. These are template values, not proof that every different padding value crashes the engine. Do not include a DUMMY entry in the active game count.

5. Retained Fields Are Not Necessarily Active Options

The original title_mode_top also contains motion_basename, motion_chara, motion_label, scroll_frame and scroll_variable. No reader for these fields was found in the shipped PCE selection/demo path. Preserve them for compatibility, but do not describe them as five mandatory native animation settings. Likewise, the presence of a profile field or a setter does not prove a hardware effect.

6. Lineup, Language and Hardware Region Are Separate

  • titleNum counts the PCE lineup; titleNumTG counts the TG16 lineup (34 and 24 in the examined package).
  • The +100 menu offset supplies translated text and sorting data. Normal launch reads ScreenMode and offsets from the base lineup half.
  • Profile country="jp" or "us" sets the emulated controller-port region bit. It does not select PAL video, a menu language or a ROM by itself.

7. Controller Type Is a Bitmask

tg16pad_type=5 means two-button pads, multitap enabled and auxiliary inputs matched per port. Six-button protocol is bit 1 (mask 2), so 3 and 7 enable it with multitap. Menu players, runtime player_num, logical player_input_num and the pad protocol serve different purposes. See the complete pad table.

8. ScreenMode Crops the Source Image

It does not select an HDMI resolution, alter the ROM's VDC registers or have the same crop table for every core. In R-Type's TG16 configuration, mode 4 selects 336 pixels at x=8 from a 352-pixel raster. EmuOfsX/Y are source-pixel crop offsets; the generic renderer ignores them when the descriptor has no explicit crop. See the per-core tables.

9. overdrive Is Run-Ahead, Not a Speed Setting

For overdrive=N > 0, an update with video output advances the kept game state by one frame, temporarily simulates N more frames using the current inputs, displays the last image and restores the kept state. It does not skip N frames when a button is pressed, simulate every possible button combination or increase normal game speed. More run-ahead costs more CPU work. See the worked example.
