Format PSB

Animation blend modes, RGB gain, defaults and native evidence from the PC Engine Mini engine.

PSB stores structured resources such as configuration, texture atlases and animation timelines. See MZS / PSB Format for the binary container and encryption wrapper, and Cover Motion PSBs for the animation tree.

Animation content: bm

object.<name>.motion.<name>.layer[].frameList[].content.bm combines a composition selector with an RGB gain. It controls how the sprite is combined with pixels already drawn. The native default is 16 (0x10).

bmHexCompositionRGB gain after tinting
00x00Normal alpha×1
10x01Additive×1
16 (default)0x10Normal alpha×2
170x11Additive×2
190x13Multiply×2
200x14Screen×2

The ordinary composition selector is bm & 0xff0f: the color quartet in bits 4–7 is removed. For the values above, this equals bm & 0x0f. Bit 0x10 doubles RGB after multiplication by the vertex tint. Alpha is unchanged by that gain. The ×1 Multiply/Screen variants are 3/4. Higher filter selectors also exist; this table is not an exhaustive enum of every M2 effect.

Colors and the ×2 gain

The native ×2 shader performs these operations in this order:

vec4 tmp = texture2D(u_texUnitId, v_texCoord);
tmp *= v_color;
tmp.rgb += tmp.rgb;

Without an explicit color, the default bm=16 starts with 0x808080ff: midpoint RGB compensates the ×2 gain. Without the color quartet (for example bm=0 or 1), the implicit tint is white 0xffffffff. This is an 8-bit convention: 2 × 128/255 = 256/255 before subsequent rounding and saturation.

An explicit color is preserved, whether it is one RRGGBBAA integer or four corner colors [TL, TR, BL, BR]. Gray is a real tint, including its alpha. A white tint under bm=16/17 can brighten the source up to ×2; it must not be silently replaced with neutral gray. The gain changes neither opa nor the alpha channel.

Presence mask and per-frame defaults

The original reader reads bm only when content.mask & 0x20000 is set. Merely adding a JSON key does not activate it. The color presence bit is 0x200. For example, this selects additive ×2 with a nominally neutral tint:

"content": {
  "mask": 131584,
  "bm": 17,
  "color": 2155905279
}

Here 131584 = 0x20200 and 2155905279 = 0x808080ff. In a complete sprite content object, preserve the other properties and their mask bits. Without the bm bit, the reader uses 16. Without an explicit color it resolves the neutral tint for that frame; a previous frame's special blend or explicit tint is not its default.

Composition equations and alpha

Let C = texture.rgb × vertexColor.rgb × gain, A be the final source alpha after texture, tint and opacity, and D be destination RGB. Component by component, ignoring rounding and saturation:

Normal:   A*C + (1-A)*D
Additive: D + A*C
Multiply: D*(1-A + A*C)
Screen:   D + (1-D)*A*C
CompositionFragment RGBGL srcRGB / dstRGBGL srcAlpha / dstAlpha
NormalStraightSRC_ALPHA / ONE_MINUS_SRC_ALPHAONE / ONE_MINUS_SRC_ALPHA
AdditiveStraightSRC_ALPHA / ONEZERO / ONE
MultiplyPremultiplied by ADST_COLOR / ONE_MINUS_SRC_ALPHAZERO / ONE
ScreenPremultiplied by AONE_MINUS_DST_COLOR / ONEZERO / ONE

All four use GL_FUNC_ADD. Additive, Multiply and Screen preserve destination alpha. Premultiplication is selected by the composition, independently of bit 0x10. This matters for translucent pixels whose doubled RGB exceeds one: the normal/additive source is clamped as straight RGB before the blend factors apply, whereas the Multiply/Screen fragment is premultiplied before that clamp.

bm=0 is normal transparency. An opaque draw can let the engine disable blending as an optimization, but bm=0 is not a general framebuffer Copy operation.

Native evidence and scope

These meanings come from the original ARM executable, rather than from names assigned by a viewer. Examined SHA-256: b02848f66b82f8ac3090db523c4db9633508f9e3f53c7dc0ee3d01ce8aee8792.

  • 0x14f4d4–0x14f4e8: default bm=16; 0x14f51c and 0x14fea4: mask gate and integer read.
  • 0x1b95e4: blend/shader selection; 0x2162a4: shader with tmp.rgb += tmp.rgb.
  • 0x1b761e: additive; 0x1b72e2: Multiply; 0x1b76d4: Screen.

Targeted synthetic ARM execution checked 42 decoding cases, nine GLES branches and six original shader sources, plus default/mask and explicit-color cases. These record native control flow and GL arguments; they are not physical-console pixel measurements.

A separate scan of 24 distinct stock motion PSBs found explicit bm values 0 (304 contents), 1 (34), 17 (112), 19 (1) and 20 (300). The bm=19 example is system/motion/wall_bg06.psb.m, object bg, motion front, layer 1, labeled フィルター. Missing fields use the native defaults.
