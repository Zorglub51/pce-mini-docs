Architecture

How m2engage loads configuration, runs scripts, and renders the game selection UI.

Boot Sequence

When m2engage starts, it goes through a well-defined initialization sequence. Understanding this sequence is critical for debugging custom game packs — if your files cause a crash, the point of failure tells you which file is broken.

m2engage boot sequence 1. Platform check |- Reads /dev/i2c-1 EEPROM for hardware validation |- Accesses /tmp/sunxi_dump (patched path) |- On failure: crash with exit 99 (SIGBUS) \- No PSB files read yet 2. Native init |- Loads title_prof.psb.m <-- crash here = title_prof is bad |- Reads system_prof.psb \- Initializes Squirrel VM 3. init_system_1st() [Squirrel] |- Reads game versions from title_prof |- Registers all GAME### region tags |- 83 versions loaded (34 JP + 24 US + variants) \- Prints: "init_system_1st() : start/done" 4. init_system_preload() [Squirrel] |- Loads sound config \- Prints: "init_system_preload() : start/done" 5. init_system_create_systemdata() |- Creates backup control |- Sets screen resolution (1280x720) \- Prints: "dev_name : PceMini" 6. init_system_autoload() |- Loads save data \- Prints: "ExecAutoload: ret = 3" 7. init_system_last() \- Final initialization 8. Logo / Splash screen |- Renders Konami logo, warning screens \- Audio starts playing here 9. Title select (mode_title_select.nut) |- Loads title_mode_top.psb.m |- Reads titleNum / titleNumTG |- Creates carousel with s_titleNum motion objects |- Loads cover art from motion PSBs \- Prints: "s_titleNum = N"
Diagnostic: Where did it crash?
  • No SQ output, no sound → Crash in step 2 (native init). Check title_prof.psb.m
  • SQ output, music, black screen → Crash in step 8-9. Check title_mode_top.psb.m or motion PSBs
  • Normal init, s_titleNum printed → Issue in carousel/motion. Check sort indices and motion PSBs

Squirrel Script Engine

m2engage uses the Squirrel scripting language (statically linked, no external .dll/.so). Scripts control the entire UI flow: menus, transitions, cover art display, game launch, save management.

Key Scripts

ScriptPurpose
system/script/mode_title_select.nut Game selection carousel. Reads title_mode_top.psb, creates motion objects, handles input
system/script/game_content.nut Game loading. conv_path() resolves system/ vs 040/ prefixes
system/script/utils.nut PSB caching via s_loaded_config table and ResourceCache class

Config Loading

PSB files are loaded by scripts using util_load_config(), which takes a path like "config/title_mode_top.psb". The conv_path() function prepends either system/ or 040/ depending on the resource type. Configs are cached — each PSB is loaded only once. 

// Squirrel: loading a config
m_config = ::util_load_config( ::conv_path("config/title_mode_top.psb") );
s_titleNum = m_config["titleNum"];

Data Flow: Game Selection

Game Selection Data Flow title_mode_top.psb | |-- items[0..49] ──> JP game names, sort order, platform |-- items[50..99] ──> US game names, sort order, platform |-- items[100..149]──> EN translations of JP games |-- items[150..199]──> EN translations of US games |-- titleNum (34) ──> Number of JP games \-- titleNumTG (24)──> Number of US games | v mode_title_select.nut |-- Creates s_titleNum Motion objects |-- Each Motion loads from cover motion PSB |-- setVariable("pkg", image_index) selects which cover to show |-- Carousel: 5 visible, wraps via s_titleNum |-- Sort modes use sor_* indices | v title_jp_titleselect_jp.psb (or _us for US lineup) |-- Sprite sheet textures (1024x1024 RGBA) |-- Icon coordinate map: "0000" -> {x, y, w, h} |-- frameList: time -> icon mapping \-- "pkg" parameter selects which icon to display | v Rendered carousel on screen

File Priority

m2engage checks for extracted files first, falling back to alldata.bin:

  1. Extracted directory file (e.g., 040/config/title_mode_top.psb.m)
  2. Entry in alldata.bin via alldata.psb.m manifest

This means you can override individual files by placing them in the extracted directory structure without rebuilding the entire alldata archive.

Title Packs

The 040/ directory is for dev_id 40 (PC Engine / Japan). The system also supports dev_id 41 (TurboGrafx-16 / USA), but in the PCE Mini, both JP and US lineups are stored in the same 040/ pack. The system_prof.psb maps dev_ids to title packs: 

// system_prof.psb -> title_list
{
  "40": { "dev_name": "PceMini",    "dev_id": 40 },
  "41": { "dev_name": "TgMini",     "dev_id": 41 }
}
