Theme Selection MOD

The settings menu allows the user to choose between visual themes for the JP lineup. M2 shipped with two themes (PC Engine and CoreGrafx) but the motion PSB contains complete artwork for a third hidden theme (TurboGrafx-16). This page documents the full settings screen, the frame/theme selection sub-menu, how the chosen theme propagates across the entire UI, and the modification that exposes all three themes.

3rd Theme Modification Overview

Modification summary The titleselect_ui.psb motion file contains complete artwork for 3 theme slots (PC Engine, TurboGrafx-16, CoreGrafx) but M2 only exposed slots 0 and 2 in the shipping code. This mod exposes all 3 slots in the JP lineup's frame selection screen. 5 Squirrel source files were modified — all changes are marked with [MOD] 3rd theme: comments that explain what was changed and preserve the original code as comments.

Constant Renumbering

The constants were renumbered so they directly match the motion PSB slot indices, eliminating the remapping that the original code had to do:

Constant Original Value New Value Motion Slot Theme
FRAME_PCENGINE 0 0 (unchanged) 0 PC Engine
FRAME_TG16 — (did not exist) 1 1 TurboGrafx-16
FRAME_COREGRAFX 1 2 2 CoreGrafx
Backward compatibility The value saved in _74_frameType changes meaning — old value 1 (CoreGrafx) now means TG16. Since this runs on a modded system, no migration is needed. The systemdata_backup_flags.nut default for DEVID_US was updated from 1 to 2. The mode_title_select_settinglang.nut first-boot language selection uses the FRAME_COREGRAFX constant by name, so it automatically resolves to the new value (2) at Squirrel compile time.

Modified Files

File What Changed
const.nut Added FRAME_TG16 = 1, changed FRAME_COREGRAFX from 1 to 2
mode_title_select_setting.nut 3-slot navigation (wraps at 3), cursor positions [-178, 0, 178], direct slot mapping for screen_sel/active_slot/logoflash, initialize_us chara for TG16 save-init screen
utils.nut Added FRAME_TG16 case in getBGMotionName(), getGameStartBGMotionName(), getFrameTypeGuideText(), and MenuModeGuide color

Files that did not require changes: mode_title_select.nut (calls getBGMotionName() which handles TG16), wallpaperBG.nut (same reason), mode_title_select_settinglang.nut (uses constant name, not numeric value).

Key Design Change: Direct Slot Mapping

The original code used m_indexFrame as a 0/1 cursor index and remapped it to motion slot 0/2 in every place that set screen_sel, active_slot, or logoflash. The mod makes m_indexFrame directly equal the motion slot index (0/1/2), eliminating the remapping: 

// Original: separate cursor index (0/1) and slot index (0/2), with if/else remapping
//   if (m_indexFrame == 0) { screen_sel = 0; logoflash = 1; }
//   else                   { screen_sel = 2; logoflash = 3; }

// MOD: m_indexFrame IS the motion slot index (0/1/2) — direct mapping
m_motion_bg.setVariable("screen_sel", m_indexFrame);
m_motion_bg.setVariable("active_slot", m_indexFrame);
m_motion_bg.setVariable("logoflash", 1 + m_indexFrame);  // produces 1, 2, or 3

Cursor System (SettingCorsol)

The cursor is a separate class that uses the "cursol" chara in the same motion resource. It smoothly glides to target positions using homing movement (PointDir + TragetKinspeed_Option + DirMove).

Design Evolution

Asset evidence and a possible earlier design The motion assets contain three theme slots (PC Engine, TurboGrafx-16, CoreGrafx), while the released scripts use two lineups: the US lineup has the TurboGrafx-16 presentation, and the Japanese lineup offers PC Engine and CoreGrafx. A former single-lineup, three-theme design is an inference from those unused assets, not a documented development history. The modification described here exposes the existing TG16 assets as a third selectable theme.
Possible earlier design (inferred from assets) 1 lineup, 3 selectable themes: slot 0 = PC Engine (screen_sel = 0) slot 1 = TurboGrafx-16 (screen_sel = 1) slot 2 = CoreGrafx (screen_sel = 2) Shipping code (M2's final design) 2 lineups, theme per lineup: JP lineup → choice: PC Engine (screen_sel = 0) or CoreGrafx (screen_sel = 2) US lineup → fixed: TurboGrafx-16 (via "bg_us", no selection) Slot 1 skipped in UI → explains the 0/2 quirk MOD: 3rd theme restored JP lineup → choice: PC Engine (screen_sel = 0) or TG16 (screen_sel = 1) ← NEW or CoreGrafx (screen_sel = 2) US lineup → fixed: TurboGrafx-16 (unchanged)

Theme Propagation Across the UI

The frame type choice doesn't just affect the settings screen — it propagates to several systems throughout the UI. The key functions are defined in system/script/utils.nut and consumed by the title select screen and the wallpaper background class.

JP lineup only The frame type setting only affects visuals when the JP (PC Engine) lineup is active. When the US (TurboGrafx-16) lineup is selected, all theme-dependent code uses fixed US-specific values — the frame type is ignored entirely. This is consistent throughout: getBGMotionName(), getFrameTypeGuideText(), MenuModeGuide color, and the save init screen chara all check the lineup first and bypass the frame type when on US.

Background Motion Character

getBGMotionName() (utils.nut) is the primary mechanism. It returns the motion chara name for all background layers based on the current lineup and frame type:

Lineup Frame Type Chara Returned
US (ignored) "bg_us" — always
JP PC Engine (0) "bg"
JP TG16 (1) NEW "bg_us"
JP CoreGrafx (2) "bg_eu"

This chara is applied to three sets of motion objects on the title select screen (mode_title_select.nut):

  • m_motion_bg — upper background, motion "main"
  • m_motion_bg_down — lower background, motion "main_down"
  • m_motion_bg_back[] — scrolling background array (×BGBACK_NUM), motion "back"

There is also getGameStartBGMotionName() which returns the same values and is used when launching a game.

Hot-reload after settings change When the user exits settings, mode_title_select.nut compares frameTypeOld with the current value. If changed, it checks s_last_linenp == LINEUP_JP before reloading — on the US lineup the chara is always "bg_us" so no reload is ever needed.

WallpaperBG Class

The WallpaperBG class (system/script/wallpaperBG.nut) manages background visuals during transitions (e.g. returning from game to menu). It also uses getBGMotionName() — no modification needed since it inherits TG16 support from that function.

Frame Offset Animation (Startup Convergence)

On program launch, the different parts of the UI converge from outside the screen toward the center. Three functions in utils.nut manage this:

Function Description
setFrameinOut() Triggers animation by setting s_frame_offset = 30
FrameinOutExec() Called each frame in the main loop; decrements s_frame_offset toward 0
getFrameOffset() Returns (s_frame_offset²) / 3 — quadratic ease-in (fast start, smooth settle)

At frame 0 the offset is 900/3 = 300 pixels, pushing UI elements far off-screen. It decays quadratically over 30 frames until it reaches 0. The offset is applied to every major element's position, creating the convergence effect. No modification needed — the convergence animation is theme-agnostic.

Guide Button Icons

getFrameTypeGuideText() (utils.nut) remaps button icon characters depending on the lineup and theme. The custom font uses Cyrillic/Greek characters as symbol codes for controller button glyphs:

Default Icon PCE (JP) TG16 (JP) CoreGrafx (JP) US Lineup
Ι (Iota) Ι (unchanged) И (I) NEW Ж (Zhe) И (I)
Κ (Kappa) Κ (unchanged) Л (El) NEW Б (Be) Л (El)
Μ (Mu) Μ (unchanged) Ц (Tse) NEW Г (Ge) Ц (Tse)
Λ (Lambda) Λ (unchanged) П (Pe) NEW б (be) П (Pe)

TG16 uses the same icon remapping as the US lineup — the TG16 controller has the same button layout as the TurboGrafx-16 pad.

Guide Text Color

The MenuModeGuide class (utils.nut) can optionally tint guide text based on the frame type. When colorChange = true:

  • JP + PC Engine → blue text prefix: #{color,00000FF}
  • JP + TG16 → no color change (default text color) NEW
  • JP + CoreGrafx → no color change (default text color)
  • US lineup → no color change (frame type ignored)

Initial Language Selection

On first boot, the language selection screen (mode_title_select_settinglang.nut) auto-sets the frame type based on the chosen language. This only applies to the US/EU retail version (DEVID_US). The code uses the FRAME_COREGRAFX constant by name, so it automatically resolves to the new value (2) at compile time — no code change needed.

Language Frame Type Default Lineup
Japanese PC Engine (0) (unchanged)
English CoreGrafx (2) was 1 (unchanged)
French CoreGrafx (2) JP
Italian CoreGrafx (2) JP
German CoreGrafx (2) JP
Spanish CoreGrafx (2) JP
European languages set JP lineup On the US/EU retail version, choosing French, Italian, German, or Spanish not only sets the CoreGrafx frame but also switches the default lineup to JP (PC Engine games). This makes sense because the EU version was sold as "CoreGrafx Mini" and these languages were targeted at the European market.
