Format PSB

Animation blend modes, presence masks, interpolation, defaults and native evidence from the PC Engine Mini engine.

PSB stores structured resources such as configuration, texture atlases and animation timelines. See MZS / PSB Format for the binary container and encryption wrapper, and Cover Motion PSBs for the animation tree.

Animation content: bm

object.<name>.motion.<name>.layer[].frameList[].content.bm combines a composition selector with an RGB gain. It controls how the sprite is combined with pixels already drawn. The native default is 16 (0x10).

bmHexCompositionRGB gain after tinting
00x00Normal alpha×1
10x01Additive×1
16 (default)0x10Normal alpha×2
170x11Additive×2
190x13Multiply×2
200x14Screen×2

The ordinary composition selector is bm & 0xff0f: the color quartet in bits 4–7 is removed. For the values above, this equals bm & 0x0f. Bit 0x10 doubles RGB after multiplication by the vertex tint. Alpha is unchanged by that gain. The ×1 Multiply/Screen variants are 3/4. Higher filter selectors also exist; this table is not an exhaustive enum of every M2 effect.

Colors and the ×2 gain

The native ×2 shader performs these operations in this order:

vec4 tmp = texture2D(u_texUnitId, v_texCoord);
tmp *= v_color;
tmp.rgb += tmp.rgb;

Without an explicit color, the default bm=16 starts with 0x808080ff: midpoint RGB compensates the ×2 gain. Without the color quartet (for example bm=0 or 1), the implicit tint is white 0xffffffff. This is an 8-bit convention: 2 × 128/255 = 256/255 before subsequent rounding and saturation.

An explicit color is preserved, whether it is one RRGGBBAA integer or four corner colors [TL, TR, BL, BR]. Gray is a real tint, including its alpha. A white tint under bm=16/17 can brighten the source up to ×2; it must not be silently replaced with neutral gray. The gain changes neither opa nor the alpha channel.

Presence mask and per-frame defaults

The original reader reads bm only when content.mask & 0x20000 is set. Merely adding a JSON key does not activate it. The color presence bit is 0x200. For example, this selects additive ×2 with a nominally neutral tint:

"content": {
  "mask": 131584,
  "bm": 17,
  "color": 2155905279
}

Here 131584 = 0x20200 and 2155905279 = 0x808080ff. In a complete sprite content object, preserve the other properties and their mask bits. Without the bm bit, the reader uses 16. Without an explicit color it resolves the neutral tint for that frame; a previous frame's special blend or explicit tint is not its default.

Animation content: mask

No property reads were found for bits 22, 28 or 31 in these native routines. They are absent from the examined corpus; this does not assign them a universal meaning across other M2 engine versions. The table establishes field selection, not the complete visual semantics of the uncommon bp, stc, model or feedback effects.

The three paired gates are genuine groups: mask=0x20 reads both zx and zy. Stock files set paired bits together (0x0c, 0x60, 0x180); writers should supply both keys. src and icon have no presence bit and are read independently for layer types 0, 3, 6, 11 and 12.

Disabled-field defaults are origins, coordinates, flips, angle and shear at zero; scales at one; opa=255, bm=16, bp=0 and ti=0. Color uses the neutral tint described above. All 5,602 stock contents contain a mask. These defaults describe disabled bits; they do not define malformed files that omit a required key while enabling its bit.

Curves, occ and keyframe types

Only frameList[i].type == 3 interpolates toward the following content frame and reads the five curve references or ti. Type 2 holds its values. This is the keyframe type, independent of the layer type. Twelve stock type-2 contents have a ccc key and bit, which the native reader ignores.

occ eases the four RGBA corner colors. The separate opa property stays linear, rounded to an integer. Color interpolation uses the native 8-bit weight trunc(easedT * 256); an endpoint without explicit color contributes its own default tint. ccc eases coordinates, not motion.timeOffset.

elapsed = currentTime - previousKeyTime;
if (ti != 0) elapsed = ti * trunc(elapsed / ti);
t = elapsed / (nextKeyTime - previousKeyTime);

The quantized time factor is passed to each enabled curve. Without a curve the corresponding interpolated property uses the linear factor.

Nested motion.mask

The outer content.mask & 0x80000 enables the object. Its own motion.mask then selects these fields:

BitGateFieldDefault
00x01flags, integer0
10x02dt, integer1
20x04docmpl, booleanfalse
30x08dofst, floating point0
40x10dtgt, stringempty

timeOffset has no bit in the nested mask. It is read whenever the outer motion bit is enabled. All 1,224 motion objects in the corpus use motion.mask=0 while containing a valid timeOffset.

Nested prt.mask

The outer content.mask & 0x100000 enables the particle object. Its nested mask selects parameter groups; bits 0 and 1 do not select X/Y position axes.

The 36 particle objects use mask 2 (8 objects), 3 (13 objects), or 27 / 0x1b (15 objects). In particular, 27 selects trigger, frame interval, angle and scale groups. A disabled group retains its native defaults.

layer.inheritMask separately controls parent-property inheritance. A key named mask inside layerIndexMap can simply be a layer name mapped to an index. Neither is a content.mask value.

m2engage-mac implementation

The 2D port applies these presence gates to its supported animation fields, resets defaults per content, restricts curves and ti to type 3, and applies occ to RGBA independently of opacity. Particle parameters are decoded through both masks; spatial randomization no longer interprets prt.mask as axes. Prepared motion cache version 4 rejects older interpretations and falls back to the source JSON; regenerate caches with the updated resource preparer.

Additional motion controls and particle vmin/vmax/range are decoded and retained. Their native rendering/physics effects, action dispatch, camera/anchor/model/mesh/feedback effects and stc/bp effects remain outside the port's supported 2D behavior. Recognizing a native presence bit does not imply those effects are implemented.

Composition equations and alpha

Let C = texture.rgb × vertexColor.rgb × gain, A be the final source alpha after texture, tint and opacity, and D be destination RGB. Component by component, ignoring rounding and saturation:

Normal:   A*C + (1-A)*D
Additive: D + A*C
Multiply: D*(1-A + A*C)
Screen:   D + (1-D)*A*C
CompositionFragment RGBGL srcRGB / dstRGBGL srcAlpha / dstAlpha
NormalStraightSRC_ALPHA / ONE_MINUS_SRC_ALPHAONE / ONE_MINUS_SRC_ALPHA
AdditiveStraightSRC_ALPHA / ONEZERO / ONE
MultiplyPremultiplied by ADST_COLOR / ONE_MINUS_SRC_ALPHAZERO / ONE
ScreenPremultiplied by AONE_MINUS_DST_COLOR / ONEZERO / ONE

All four use GL_FUNC_ADD. Additive, Multiply and Screen preserve destination alpha. Premultiplication is selected by the composition, independently of bit 0x10. This matters for translucent pixels whose doubled RGB exceeds one: the normal/additive source is clamped as straight RGB before the blend factors apply, whereas the Multiply/Screen fragment is premultiplied before that clamp.

bm=0 is normal transparency. An opaque draw can let the engine disable blending as an optimization, but bm=0 is not a general framebuffer Copy operation.

Native evidence and scope

These meanings come from the original ARM executable, rather than from names assigned by a viewer. Examined SHA-256: b02848f66b82f8ac3090db523c4db9633508f9e3f53c7dc0ee3d01ce8aee8792.

  • 0x14f4d4–0x14f4e8: default bm=16; 0x14f51c and 0x14fea4: mask gate and integer read.
  • 0x1b95e4: blend/shader selection; 0x2162a4: shader with tmp.rgb += tmp.rgb.
  • 0x1b761e: additive; 0x1b72e2: Multiply; 0x1b76d4: Screen.

Targeted synthetic ARM execution checked 42 decoding cases, nine GLES branches and six original shader sources, plus default/mask and explicit-color cases. These record native control flow and GL arguments; they are not physical-console pixel measurements.

A separate scan of 24 distinct stock motion PSBs found explicit bm values 0 (304 contents), 1 (34), 17 (112), 19 (1) and 20 (300). The bm=19 example is system/motion/wall_bg06.psb.m, object bg, motion front, layer 1, labeled フィルター. Missing fields use the native defaults.

Presence-mask evidence

The mask investigation executes 92 synthetic native-reader cases: 64 isolated content-bit routes (all 32 bits for keyframe types 2 and 3), six metadata cases, 16 nested-mask routes and six zero-mask/default cases. PSB accessors, conversions and allocations are simulated; branch selection and default stores come from the original ARM instructions.

A scan of 24 distinct stock PSBs finds 5,602 contents, 117 mask values and 19 used bits, with no key/presence-gate mismatch. Native entry points are 0x140334 (metadata), 0x14f47c (content) and 0x1579c0 (interpolation). This is the PC Engine Mini reader's schema, not a universal PSB animation standard.
