Pitfalls & Gotchas

Hard-won lessons from debugging custom game packs. Each of these cost hours to figure out.

1. Sorting Indices Out of Range

Symptom: Black screen with music playing SQ output looks normal, music plays, but the screen is completely black.

The Problem

The sor_* fields in each game item (sor_name, sor_date, sor_demo, sor_genr, sor_pnum) are used as array indices by the Squirrel scripts. The scripts create arrays of size s_titleNum and then use sor_* to index into them.

If you reduce titleNum from 34 to 10 but leave the original sort indices (some reaching up to 33), the script does: 

// mode_title_select.nut, line ~2510
for ( i = 0; i < s_titleNum; i++ )  // s_titleNum = 10
{
    local index = getPkgIndex( i, m_sort, m_config );
    s_indextable[index] = i;   // index could be 33 -> OUT OF BOUNDS!
}

Squirrel's array out-of-bounds doesn't throw a visible error — it silently corrupts the VM state, causing the rendering to fail without any error message in the SQ logs.

The Fix

Every sor_* value must be in range [0, N-1] where N is titleNum (for JP items) or titleNumTG (for US items). The simplest approach: set each item's sor_* to its position within the 50-item section. 

# Python: fix sort indices
for i in range(200):
    section_pos = i % 50
    for key in ['sor_date', 'sor_demo', 'sor_genr', 'sor_name', 'sor_pnum']:
        items[i][key] = section_pos

2. title_prof Missing root Wrapper

Symptom: No SQ output, no sound, immediate black screen m2engage crashes during native init before any scripts execute.

The Problem

The title_prof.psb.m file must have its data wrapped in a root object. The native C++ parser expects this exact structure and crashes without it. 

// WRONG - causes crash
{
  "m2epi": { "version": { ... } },
  "game_versions": { ... }
}

// CORRECT
{
  "root": {
    "m2epi": { "version": { ... } },
    "game_versions": { ... },
    "controller": { ... },
    "player_num": 6,
    "replay": { ... },
    "title": { "dev_name": "PceMini" },
    "wallpaper": { ... }
  }
}

The Fix

Always wrap title_prof data in {"root": { ... }}. Include all 7 expected sections. Note: player_num is a plain integer (6), not a dict.

2b. title_prof Wrong Field Names

Symptom: No SQ output, no sound, immediate black screen Identical to the missing root crash. The native parser rejects unknown field names.

The Problem

The native C++ parser expects exact field names in certain sections. Using plausible-but-wrong names silently crashes: 

// WRONG — crashes native parser
"replay": {
  "fps": 60,                  // not a real field
  "record_sec": 90            // not a real field
}
"wallpaper": {
  "motion_file": "...",       // wrong name
  "num": 1                    // wrong name
}

// CORRECT
"replay": {
  "init_replay_record_time": 60,
  "max_replay_record_time": 60,
  "replay_record_time_list": [0, 30, 60]
}
"wallpaper": {
  "datafile": "motion/bg%02d.psb",
  "max_num": 1
}

The Fix

Copy field names exactly from the original. When in doubt, extract the original title_prof.psb.m and compare field-by-field. See the title_prof reference for the complete field list.

3. MZS Filename Sensitivity

Symptom: "Decrypted data is not zstd" error from mzstool

The Problem

The MZS encryption key is derived from the filename. If you rename a .psb.m file, the decryption key changes and the file becomes unreadable. 

# This works:
mzstool.py extract title_mode_top.psb.m

# This fails (wrong key derived from "renamed"):
cp title_mode_top.psb.m renamed.psb.m
mzstool.py extract renamed.psb.m
# -> ValueError: Decrypted data is not zstd (magic: 0x9a7b8864)

The Fix

Always keep the original filename when extracting or building.

4. DUMMY Entry Differences

Subtle: Doesn't crash but may cause unexpected behavior

The Problem

DUMMY entries in the original data have players: 1 and demo_time: 6180, but it's tempting to use players: 0 (since dummy games have no players) and different demo_time values.

The Fix

Match the original DUMMY template exactly:

  • players: 1 (not 0)
  • demo_time: 6180
  • regionTag: "DUMMY"
  • sor_*: section_index (see Pitfall #1)

5. Missing Top-Level Keys in title_mode_top

Symptom: Rendering glitches or missing animations

The Problem

Besides items, titleNum, and titleNumTG, the title_mode_top file has five additional top-level keys used by the native animation engine: 

"motion_basename": "title_grandmenu",
"motion_chara": "grandmenu",
"motion_label": "stand",
"scroll_frame": 10,
"scroll_variable": "gametitle_normal"

The Fix

Always include all eight top-level keys. Copy these five values verbatim from the originals.

6. titleNum / titleNumTG Swapped

Symptom: Wrong game count per lineup, carousel behaves oddly

The Problem

The naming is counterintuitive:

  • titleNum = JP/PCE game count (34 in original)
  • titleNumTG = US/TG16 game count (24 in original)

It's easy to swap these, especially since the script uses them via a conditional: 

if (s_last_linenp == LINEUP_JP)
    s_titleNum = m_config["titleNum"];      // JP count
else
    s_titleNum = m_config["titleNumTG"];    // US count

7. Stale gl_proxy / Shared Memory

Symptom: m2engage hangs, gl_proxy shows "Ready" but nothing happens

The Problem

When running on the VM setup (virgl + qemu-user), a leftover gl_proxy process from a previous session can hold the /dev/shm/m2e_gl shared memory file. New instances get confused.

The Fix

# Before launching:
pkill -9 -f gl_proxy
pkill -9 -f m2engage
rm -f /dev/shm/m2e_gl
sleep 1
# Now launch run.sh

8. Platform Check Intermittent Crash

Symptom: Exit code 99 (SIGBUS), "platform read failed" message

The Problem

m2engage's hardware platform check (i2c EEPROM read) occasionally triggers a SIGBUS under qemu-user emulation. This is non-deterministic and timing-sensitive.

The Fix

The run.sh script auto-retries on exit code 99, up to 10 attempts. Don't confuse this crash with a PSB-related issue — it happens before any config files are loaded.
