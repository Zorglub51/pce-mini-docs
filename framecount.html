FrameCount Native

The g_frameCount global object — a native C++ SQFrameCount class exposed to Squirrel via Sqrat binding. Controls application lifecycle, shutdown sequencing, save state checking, and debug logging.

Table of Contents

  1. Overview
  2. Method Reference
  3. Shutdown Flow
  4. Gameplay Gating
  5. Save State Checking

1. Overview

g_frameCount is a global Squirrel object backed by the native C++ class SQFrameCount (bound via Sqrat, the Squirrel C++ binding library). The binary also references MFrameCountTask, suggesting it runs as a persistent task within m2engage's frame loop.

It serves as the central coordination point for:

  • Application lifecycle — shutdown detection and execution
  • Gameplay state — gating shutdown during active menus
  • Save state metadata — checking file existence, creating init markers
  • Debug logging — writing trace messages to a log file
  • Memory management — triggering Squirrel garbage collection

2. Method Reference

Method Signature Description
logFileWrite(msg) string → void Write a message to the debug log file. Used extensively for execution flow tracing.
sqgc() void → void Trigger Squirrel VM garbage collection. Called once at app startup.
getFinishSeq() void → int Query the shutdown sequence state. Returns 0 for normal operation, >0 when shutdown is requested (e.g., power button pressed).
setFinishSeq(seq) int → void Set the shutdown sequence state. Use 2 to request shutdown.
appFinish() void → void Terminate the application. Called after setFinishSeq(2) to execute the actual shutdown.
setGamePlay(status) int → void Set the gameplay status flag. 1 = gameplay/settings active, 0 = idle. Prevents shutdown during active menus.
initfileSave() void → void Create the save initialization marker file (save/.game_noinit). Called after the first saved state, and by autosave when backup flags or SRAM differ from initialized defaults.
stateFileExist(fileid) int → bool Check if a save state file exists for the given file ID. Used by the title select screen to show save slot indicators.

3. Shutdown Flow

m2engage detects hardware power button presses through getFinishSeq(). Multiple scripts poll this value in their main loops. When a shutdown is detected, the two-step sequence is:

Shutdown Sequence Main Loop (mode_title_select / pause_main / settings) | | Poll: local fseq = ::g_frameCount.getFinishSeq(); | if (fseq > 0) → shutdown detected | Shutdown Request | | ::g_frameCount.setFinishSeq(2); // signal shutdown | ::g_frameCount.appFinish(); // execute shutdown | Application exits

Polling Locations

Script Context
mode_title_select.nut Title selection main loop — checks for power-off during menu browsing
mode_title_select_setting.nut Settings menu — checks for power-off during settings interaction
mode_title_select_settinglang.nut Language selection — checks for power-off, handles shutdown with setFinishSeq(2) + appFinish()
pause_main.nut In-game pause menu — only logs, does not initiate shutdown from here

4. Gameplay Gating

setGamePlay() acts as a gate to prevent shutdown while the user is actively interacting with settings menus. The pattern: 

// Entering settings screen
::g_frameCount.setGamePlay(1);    // mark: user is in settings

// ... settings menu logic ...

// Leaving settings screen
::g_frameCount.setGamePlay(0);    // mark: user left settings

This is only used in mode_title_select_setting.nut. The native code presumably checks this flag before allowing appFinish() to proceed, ensuring settings changes are saved before shutdown.

5. Save State Checking

stateFileExist(fileid)

Used by the title select screen to display save slot indicators (small icons showing which of the 4 save slots have data). The file ID is calculated from the game’s sorted index and the lineup offset: 

// mode_title_select.nut, nameTextUpdate()
local sortindexLineup = s_indextable[selectindex] + getLinenpIndexOffset();
for (local i = 0; i < 4; i++) {
    local fileid = i + (sortindexLineup * 4);
    if (::g_frameCount.stateFileExist(fileid) == true) {
        // set saveslot indicator visible
    }
}

See Save System → Per-Game Slot Numbering for the full slot calculation details.

Limitation stateFileExist() takes only a fileid parameter — it does not accept the segment type (011 vs 012). It is unclear how it determines which file type to check. The original commented-out code used BackupStatedata.check_exist_state_data(fileid) instead, which goes through the backup manager and correctly handles segment types.

initfileSave()

Creates the save/.game_noinit sentinel file. The pause menu calls it after saving a state; SystemData::TryAutosave() also creates or deletes it depending on whether backup flags or SRAM differ from initialized defaults (systemdata_saveload.nut). It therefore does not prove that a save state exists. Called from pause_main.nut after the first save: 

// pause_main.nut, after saving state data:
::g_systemdata.get_value(SystemDataValueIndex.BACKUP_FLAGS).set_73_stateSavet(1);
// "Once state is saved even once, create initialization file"
::g_frameCount.initfileSave();

The complementary initfileDelete() function also exists in the binary (presumably called during factory reset / data initialization) but is not used in any known Squirrel script.
