title_prof config

ROM selection, emulator options, input defaults and shared session settings. This reference separates values read by the stock scripts from effects actually implemented by the original PC Engine cores.

Jump to: game parameters · run-ahead · controller types · timing bits · input mappings · SRAM · replay/backgrounds · conditional fields.

Scope of the reference The findings below apply to the original ARM m2engage executable with SHA-256 b02848f66b82f8ac3090db523c4db9633508f9e3f53c7dc0ee3d01ce8aee8792. They come from the shipped Squirrel scripts, native disassembly and targeted execution probes. A framework option being read does not establish that the selected core implements it.

Loading, Structure and Precedence

040/config/title_prof.psb.m
040/config/title_prof_specdepend.psb.m

The resource layer decrypts/decompresses and parses the PSB. The stock game_content.nut:_get_title_prof() then reads its root member, merges the platform-specific profile into it, and caches the resulting table. The settings contract is implemented by Squirrel readers and the native functions they call. It is not a native parser with a fixed seven-section schema.

// Stock game_content.nut:975; path constants abbreviated here.
local title_prof      = ::util_load_config(title_prof_path).root;
local title_prof_spec = ::util_load_config(title_prof_spec_path).root;
title_prof = ::merge_tables(title_prof_spec, title_prof);

The root wrapper is therefore needed for this stock reader. Later code uses title_prof.m2epi, for example, rather than title_prof.root.m2epi. The retail PceMini profile contains these seven sections; this is an observed layout, not proof that every section is unconditionally required by a native schema:

root |- controller input mappings and rapid fire |- game_versions version IDs and menu text keys |- m2epi emulator defaults | \- version per-game configuration, keyed by version tag |- player_num shared session player count |- replay replay durations |- title package/title identity \- wallpaper background resources
  • title_prof_specdepend is merged recursively over the base profile. Arrays are merged by index; a shorter override does not remove the existing tail. Whether nested array entries are merged depends on the source array's first element type.
  • For ordinary emulator options, priority is m2epi.version[tag].key → m2epi.key → the reader's default.
  • arch, country and rom are read from the selected version only.
  • attr is selected as one whole table: a version table replaces the global table. string instead merges names, with version values overriding matching global names.
  • player_num, player_input_num and rapid_speed_list have their own fallback rules described below. Shared SRAM and package settings do not automatically gain version overrides.
Diagnosing a broken profile Invalid PSB data, missing members used without a guard, wrong types and missing resources can fail at different stages. A lack of script output does not by itself identify title_prof or prove that the failure occurred before Squirrel started.

Per-Game Emulator Parameters

Unless a row says otherwise, these keys can be placed in m2epi as shared defaults or in m2epi.version[tag] as an override. Defaults below are the stock reader's fallback values, rather than a recommendation to add every key to every profile.

KeyValues / defaultEffect
archVersion only: "tg16", "tg16cd", "sgx" Selects the HuCard, CD or SuperGrafx core. Names are case-sensitive. The ROM extension does not select the core. The helper falls back to an empty string, which is not a usable core selection.
countryVersion only: "jp" / "us"; directly accessed Hardware region presented through the controller bus: jp sets bit 0x40, us clears it. Other strings use the Japanese constructor fallback. This does not select a PAL refresh rate.
romVersion only: relative path The file to load, resolved through conv_path() for the selected package. Use the path convention expected by the resource loader, such as roms/KungFu_J.pce; encrypted .m resource handling is separate. Missing values fall back to an empty path.
preampNumber, default 0.0 dB Relative audio gain in decibels. 0 keeps the reference level, +6 is approximately twice the signal amplitude, −6 approximately half. Positive gain can clip. It is added to the driver's and architecture's gain settings, then truncated to centi-dB; it is not a percentage.
overdriveInteger, default 0 Run-ahead for input latency reduction. N > 0 displays a simulation N frames ahead while keeping the normal one-frame state progression. Extra simulation costs CPU time. Algorithm and example.
brightnessNumber, default 1.0 Sets the same tint multiplier on the display's RGB channels. 0 is black and values between 0 and 1 dim the image. The traced 8-bit tint path clamps 255 × value to 255, so values above 1 do not provide additional gain in that path. The emulated VDC palette is unchanged.
tg16pad_typeInteger, low 3 bits; default 1 Controller protocol and input routing: multitap, six-button protocol and auxiliary inputs. Complete table below. In particular, 5 still selects the two-button protocol.
tg16_optionInteger, low 4 bits; default 0 Architecture-dependent timing options. Value 1 changes VBlank timing; value 4 provides extra CPU cycles on selected scanlines in the HuCard core. Bit definitions below.
tg16_hblankInteger, low 8 bits; default packed value 0 Sets vdp_tg16.hstart. Values 0–9 select the native default 87; 10–255 use that value. Adjusts horizontal sequencing, not the image width in pixels. TG16 and TG16CD consume it; SGX does not. Sapphire specifies 100.
tg16cd_systemcardString: "super", "arcade", other/absent TG16CD only. super selects hardware mode 1; arcade selects mode 2 and allocates an additional 2 MiB of Arcade Card RAM. Other values select mode 0. This is a hardware configuration, not a BIOS filename.
use_analogBoolean, default false true disables the normal merging of the left stick into digital directions. It does not add analog hardware or analog controls to a PC Engine game.
directionInteger/string; only tostring() == "4" is special 4 converts stick movement into four cardinal sectors with a radial dead zone. Other values use the ordinary X/Y thresholds, allowing diagonals. It does not change the number of controller buttons.
view_splitTwo positive integers [X,Y]; default [1,1] Subdivides the display mesh into X×Y pieces. It does not enable split-screen multiplayer. The native Y setter compares the new Y against the old X instead of the old Y, so some changes can skip rebuilding the mesh. No small fixed upper bound was established by this audit.
sram_supportBoolean, default false Enables the stock scripts' SRAM synchronization and related menu options. Disabling it does not remove backup RAM from the emulated hardware or disable save states. All versions in the examined retail profile inherit false.

What overdrive Does

overdrive aims to make controls feel more responsive. It is not a CPU speed multiplier, and the game does not skip forward by N frames when a button is pressed.

For each normal update, with N > 0 and a video buffer available, the native task:

  1. Runs one frame using the current inputs.
  2. Saves the resulting machine state.
  3. Runs N additional frames using those current inputs and displays the last image.
  4. Restores the saved state from step 2.

The lasting game state advances by one frame; the displayed image comes from N simulated frames later. This is repeated continuously. The next update starts from the restored state and uses newly sampled inputs. The engine does not calculate every possible direction and button combination, and it does not know future inputs.

Practical example Suppose a game's own input handling takes two frames to show a shot. With overdrive = 2, those extra simulated frames can already contain the shot, so the current display update can show it sooner. The normal game timeline still advances by one frame. The benefit depends on the game's own delay and the machine's ability to finish the extra work.

N <= 0, or an update without a video buffer, takes the normal single-frame path. Evidence: task 0x1ed238, save 0x1ef7a4 (machine command 0x203), restore 0x1ef704 (0x202). Targeted probes checked the call order and lasting state for N = −1, 0, 1, 2, 3 and 8, with and without a video buffer; they did not measure real-time audio/video performance.

The native input collector forms two groups: A[0…4] from logical slots 1–5, and B[0…4] from slots 6–10. With mask 4 clear, port i reads A[i] | B[0] | B[1] | B[2] | B[3] | B[4]; with it set, port i reads A[i] | B[i]. These are engine input slots, not proof of ten physical controller ports.

Retail examples: Kung Fu, Necromancer and J.J. & Jeff use 0; Sapphire uses 5. Other games normally inherit 1. The same pad constructor is used by all three PCE architectures. Evidence: constructor 0x77738, input collection 0x77a28, bus control/read 0x77b58/0x77b9c.

The value is masked with 15. Bits 0–1 are sent to the TG16 VDC; bits 2–3 are sent to the machine option. Their actual consumers differ by core.

Native Packing

The stock script packs architecture settings into archSubInfo before initializing the native task:

bit 0                    disable_md_6B
bit 2                    use_analog
bit 3                    direction converts to "4"
bit 4                    tg16cd_systemcard == "super"
bit 5                    tg16cd_systemcard == "arcade"
(tg16pad_type & 7) << 6
(tg16_hblank & 255) << 9
(tg16_option & 15) << 17

These are the original ARM binary's constants (0x29320–0x29390). In particular, the three shifts are 6, 9 and 17.

Version Identity and Menu Links

"game_versions": {
  "GAME000":  [0,  0, "MenuItemText__TITLE_GAME_VERSION_000"],
  "GAME002":  [2,  0, "MenuItemText__TITLE_GAME_VERSION_002"],
  "GAME002E": [52, 0, "MenuItemText__TITLE_GAME_VERSION_053"]
}

Each entry is [index, dlc_number, text_key]. The game-content reader computes the internal ID as index + dlc_number * id_threshold and retains the localization key. The PceMini profile uses DLC number 0. Its 83 version entries include variants; the IDs are not simply the visible menu positions. GAME000 is a data convention rather than a parser keyword.

A launchable title_mode_top item's regionTag and alternate version tags must resolve to available game-content versions and corresponding m2epi.version configurations. The retail profile supplies its version map in game_versions; the framework can otherwise use the table from game_content.psb. An unused menu placeholder such as DUMMY does not need a launch profile.

Suffixes such as E, S, F and T name particular retail variants; they do not define a general native suffix protocol. Their meaning comes from the menu/controller logic and the configuration attached to each tag.

Evidence and Limits

The audit covers 117 verified stock scripts and 150 attribute access paths, including two commented-out reads. Shared and per-version accesses to the same key are separate paths; this is not a count of 150 distinct, working per-game settings. The 25 distinct leaf-field patterns present in the examined retail JSON are covered. Dynamically loaded controllers may add their own contract.
