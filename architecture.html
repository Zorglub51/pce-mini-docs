Architecture

How m2engage loads configuration, runs scripts, and renders the game selection UI.

Boot Sequence

The stock scripts expose the following initialization stages. A failure near a stage helps narrow the investigation, but does not identify a broken file by itself. In particular, title_prof is interpreted by Squirrel after generic PSB loading; it is not a separate native parser with a fixed seven-section schema.

m2engage boot sequence 1. Native platform and runtime initialization \- Creates the environment used by the Squirrel scripts 2. Script bootstrap \- Enters the stock initialization scripts 3. init_system_1st() [Squirrel] |- init_game_content() loads system_prof and title_prof resources |- _get_title_prof() reads .root and merges title_prof_specdepend |- Reads game_versions from the merged profile |- Registers all GAME### region tags |- 83 versions loaded (34 JP + 24 US + variants) \- Prints: "init_system_1st() : start/done" 4. init_system_preload() [Squirrel] |- Loads sound config \- Prints: "init_system_preload() : start/done" 5. init_system_create_systemdata() |- Creates backup control |- Sets screen resolution (1280x720) \- Prints: "dev_name : PceMini" 6. init_system_autoload() |- Loads save data \- Prints: "ExecAutoload: ret = 3" 7. init_system_last() \- Final initialization 8. Logo / Splash screen |- Renders Konami logo, warning screens \- Audio starts playing here 9. Title select (mode_title_select.nut) |- Loads title_mode_top.psb.m |- Reads titleNum / titleNumTG |- Creates carousel with s_titleNum motion objects |- Loads cover art from motion PSBs \- Prints: "s_titleNum = N"
Read diagnostics as clues
  • No script output: check platform startup, resource loading and whether diagnostics are available. This alone does not prove that title_prof is malformed.
  • Music with a black menu: inspect script errors, game counts, sort ranks and motion resources.
  • s_titleNum printed: the menu read its count; later carousel or resource operations can still fail.

Squirrel Script Engine

m2engage uses the Squirrel scripting language (statically linked, no external .dll/.so). Scripts control the entire UI flow: menus, transitions, cover art display, game launch, save management.

Key Scripts

ScriptPurpose
system/script/mode_title_select.nut Game selection carousel. Reads title_mode_top.psb, creates motion objects, handles input
system/script/game_content.nut Game loading. conv_path() resolves system/ vs 040/ prefixes
system/script/utils.nut PSB caching via s_loaded_config table and ResourceCache class

Config Loading

PSB files are loaded by scripts using util_load_config(), which takes a path like "config/title_mode_top.psb". The conv_path() function prepends either system/ or 040/ depending on the resource type. Configs are normally cached in release builds; the loader also has a debug-only force_reload path. 

// Squirrel: loading a config
m_config = ::util_load_config( ::conv_path("config/title_mode_top.psb") );
s_titleNum = m_config["titleNum"];

Data Flow: Game Selection

Game Selection Data Flow title_mode_top.psb | |-- items[0..49] ──> JP game names, sort order, platform |-- items[50..99] ──> US game names, sort order, platform |-- items[100..149]──> EN translations of JP games |-- items[150..199]──> EN translations of US games |-- titleNum (34) ──> Number of JP games \-- titleNumTG (24)──> Number of US games | v mode_title_select.nut |-- Creates s_titleNum Motion objects |-- Each Motion loads from cover motion PSB |-- setVariable("pkg", image_index) selects which cover to show |-- Carousel: 5 visible, wraps via s_titleNum |-- Sort modes use sor_* indices | v title_jp_titleselect_jp.psb (or _us for US lineup) |-- Sprite sheet textures (1024x1024 RGBA) |-- Icon coordinate map: "0000" -> {x, y, w, h} |-- frameList: time -> icon mapping \-- "pkg" parameter selects which icon to display | v Rendered carousel on screen

File Priority

m2engage checks for extracted files first, falling back to alldata.bin:

  1. Extracted directory file (e.g., 040/config/title_mode_top.psb.m)
  2. Entry in alldata.bin via alldata.psb.m manifest

This means you can override individual files by placing them in the extracted directory structure without rebuilding the entire alldata archive. This file-source priority is separate from conv_path(), which chooses a title or system path by naming rules, rather than by testing which of those two directories contains a file.

Title Packs

In the examined Japanese package, 040/ is the pack for dev_id=40 (PceMini). Its two menu lineups are stored together; choosing the TG16 lineup does not switch to directory 041/. The stock system_prof.psb also declares dev_id=41 as PceMiniUSA. The relevant list entries are: 

// system_prof.psb -> root.title_list (other fields omitted)
[
  { "dev_name": "PceMini",    "dev_id": "40" },
  { "dev_name": "PceMiniUSA", "dev_id": "41" }
]

Data Flow: Game Launch

The selected regionTag connects the menu item to title_prof.m2epi.version. arch selects the native tg16, tg16cd or sgx core, which loads rom. Shared options are overridden by the selected variant where the reader supports that rule. The menu separately supplies ScreenMode and EmuOfsX/Y for source-image cropping. Menu players describes the title card; it does not configure the runtime input count or controller protocol.

See title_prof for option precedence, hardware settings and inactive fields, and title_mode_top for menu fields and the core-specific crop tables.
