Theme Selection

The settings menu allows the user to choose between the PC Engine and CoreGrafx visual themes. This page documents the full settings screen, the frame/theme selection sub-menu, and how the chosen theme propagates across the entire UI — background motions, button icons, text colors, and transition animations.

Settings Menu Overview

The settings screen is managed by system/script/mode_title_select_setting.nut. The entry point is mode_title_select_setting_main(), which creates a MenuSettingMain instance (extends MenuSettingBase).

The UI config and text strings are loaded from: 

config/mode_title_select_setting.psb

Main Menu Items

Constant Value m_mode Description
MENU_MANUAL 0 1 Digital manual
MENU_LANG 1 2 Language selection (6 languages + back)
MENU_SCREEN 2 3 Screen mode (aspect ratio, scanlines)
MENU_WALL 3 4 Wallpaper selection (4 options)
MENU_FRAME 4 6 Frame/theme selection (PC Engine vs CoreGrafx)
MENU_CREDIT 5 — Staff credits (loads mode_staff.nut)
MENU_SAVEINIT 6 5 Save data initialization (rapid-fire A to confirm)
MENU_EXIT 7 — Exit settings

Sequence Flow

SEQ_OPEN  (0)  →  15 frames of open animation ("bg_open")
SEQ_MAIN  (1)  →  Main input loop, dispatches to sub-menus via m_mode
SEQ_CLOSE (2)  →  Save all settings to BACKUP_FLAGS, play "bg_close", exit

Motion Characters

Each sub-menu switches the background motion to a different chara (character) within the same motion resource. The motion resource path is MENU_UI_TITLESELECT_MOTION_PATH.

Chara Sub-Menu Motion

"manual" Digital manual "bg"
"language" Language selection "bg"
"screen" Screen mode "bg"
"wallpaper" Wallpaper "bg"

Note The save initialization screen picks its chara based on the current frame setting: "initialize" for PC Engine, "initialize_eu" for CoreGrafx. When on the US lineup, it always uses "initialize_us".

Frame/Theme Selection (m_mode == 6)

Constants

Defined in system/script/const.nut:

Variables

Variable Type Description
m_indexFrame 0 or 1 Current cursor position (0 = PC Engine, 1 = CoreGrafx)
m_indexFrameStting 0 or 1 Confirmed/saved frame type
m_indexFrameEffectStting 0 or 1 Frame animation effect toggle (0 = off, 1 = on)

Motion Variables

These variables are set on the "frame" chara motion to control the visual state:

Variable Values Description
screen_sel 0 or 2 Selected slot (0 = PC Engine, 2 = CoreGrafx)
active_slot 0 or 2 Highlighted slot (same mapping as screen_sel)
logoflash 0, 1, or 3 Logo flash on confirm: 0 = none, 1 = PC Engine, 3 = CoreGrafx
crt 0 or 1 Frame animation effect (mirrors m_indexFrameEffectStting)

Slot index quirk — explained by cut content m_indexFrame uses 0/1, but the motion variables screen_sel and active_slot use 0/2 (not 0/1). This is because the motion assets originally had 3 slots (0 = PC Engine, 1 = TurboGrafx-16, 2 = CoreGrafx) and slot 1 was removed from the UI without renumbering. See Motion PSB Structure below.

Cursor System (SettingCorsol)

The cursor is a separate class that uses the "cursol" chara in the same motion resource. It smoothly glides to target positions using homing movement (PointDir + TragetKinspeed_Option + DirMove).

Motion PSB Structure & Design Evolution

The UI Motion File

All theme-related visuals come from a single motion PSB file: 

const MENU_UI_TITLESELECT_MOTION_PATH = "system/motion/titleselect_ui.psb";

Defined in system/script/const.nut. The file contains a single 1024×808 sprite sheet (_stream_0.png) and 339 icons, organized into 27 charas (top-level objects).

Theme-Related Charas

Chara Role Motions
bg PC Engine frame (JP) Identical structure: main, main_down, back, main_in, main_out, hucard, cdcase, boot_*, sort_*, setting_*, etc. (~80 motions each)
bg_eu CoreGrafx frame (JP)
bg_us TurboGrafx-16 frame (US)
frame Frame selection screen bg, screen_0/1/2, logo_0/1/2, logoflash_0/1/2, tile_0/1/2, screen_slot_active_jp/eu/us, screen_slot_normal, noise, etc.
initialize Save init (PCE frame) Save data initialization screens
initialize_eu Save init (CoreGrafx)
initialize_us Save init (TG16)

The three background charas (bg, bg_eu, bg_us) have strictly identical structure — same motions, same number of layers and frames. Only the icon references differ, pointing to different sprites in the texture sheet.

Three Slots in the Frame Selection Screen

The frame chara contains assets for three theme slots, not two:

Slot screen_slot_active Logo Slot Sprite Icon Logo Sprite Icon Theme
0 screen_slot_active_jp logo_0 0187 (81×44) 0188 (160×85) PC Engine
1 screen_slot_active_us logo_1 0190 (88×124) 0190 (88×124) TurboGrafx-16
2 screen_slot_active_eu logo_2 0185 (76×46) 0186 (150×92) CoreGrafx

Each slot also has: tile_N / tile_Nr (selection tiles), logoflash_N (confirmation flash animation), and screen_slot_active_*_ani (idle animation). The Squirrel code only exposes slots 0 and 2, leaving slot 1 unused.

Design Evolution

From 3 themes to 2 lineups The motion assets reveal that M2 originally planned a design where a single lineup offered 3 selectable themes (PC Engine, TurboGrafx-16, CoreGrafx). This was later changed to the final design with 2 lineups, where the TurboGrafx-16 theme became permanently tied to the US lineup via getBGMotionName() returning "bg_us", and the JP lineup retained a choice between PC Engine and CoreGrafx.
Original design (assets still present) 1 lineup, 3 selectable themes: slot 0 = PC Engine (screen_sel = 0) slot 1 = TurboGrafx-16 (screen_sel = 1) slot 2 = CoreGrafx (screen_sel = 2) Final design (shipping code) 2 lineups, theme per lineup: JP lineup → choice: PC Engine (screen_sel = 0) or CoreGrafx (screen_sel = 2) US lineup → fixed: TurboGrafx-16 (via "bg_us", no selection) Slot 1 skipped in UI → explains the 0/2 quirk

This evolution also explains several other quirks:

  • The screen_sel / active_slot values skip 1 (use 0 and 2)
  • The logoflash formula 1 + slot_value produces 1 and 3 (not 1 and 2)
  • The US lineup completely ignores _74_frameType — its theme is hardcoded in getBGMotionName()
  • There are 3 padicon charas: padicon, padicon_eu, padicon_us — matching the original 3-theme plan

Theme Propagation Across the UI

The frame type choice doesn't just affect the settings screen — it propagates to several systems throughout the UI. The key functions are defined in system/script/utils.nut and consumed by the title select screen and the wallpaper background class.

JP lineup only The frame type setting only affects visuals when the JP (PC Engine) lineup is active. When the US (TurboGrafx-16) lineup is selected, all theme-dependent code uses fixed US-specific values — the frame type is ignored entirely. This is consistent throughout: getBGMotionName(), getFrameTypeGuideText(), MenuModeGuide color, and the save init screen chara all check the lineup first and bypass the frame type when on US.

Background Motion Character

getBGMotionName() (utils.nut:2416) is the primary mechanism. It returns the motion chara name for all background layers based on the current lineup and frame type:

Lineup Frame Type Chara Returned
US (ignored) "bg_us" — always
JP PC Engine (0) "bg"
JP CoreGrafx (1) "bg_eu"

This chara is applied to three sets of motion objects on the title select screen (mode_title_select.nut):

  • m_motion_bg — upper background, motion "main"
  • m_motion_bg_down — lower background, motion "main_down"
  • m_motion_bg_back[] — scrolling background array (×BGBACK_NUM), motion "back"

There is also getGameStartBGMotionName() (utils.nut:2439) which returns the same values and is used when launching a game.

Hot-reload after settings change When the user exits settings, mode_title_select.nut (line 1271) compares frameTypeOld with the current value. If changed, it checks s_last_linenp == LINEUP_JP before reloading — on the US lineup the chara is always "bg_us" so no reload is ever needed.

WallpaperBG Class

The WallpaperBG class (system/script/wallpaperBG.nut) manages background visuals during transitions (e.g. returning from game to menu). It also uses getBGMotionName() and getFrameOffset(): 

m_motion.chara = getBGMotionName();        // upper BG
m_motion_back.chara = getBGMotionName();   // lower BG
m_motion.top = -1 * getFrameOffset();
m_motion_back.top = getFrameOffset();

for (i = 0; i < BGBACK_NUM; i++) {
    m_motion_bg_back[i].chara = getBGMotionName();  // scrolling BG
}

Frame Offset Animation (Startup Convergence)

On program launch, the different parts of the UI converge from outside the screen toward the center to form the final layout, while game thumbnails and the selection menu fade in. Three functions in utils.nut manage this:

Function Description
setFrameinOut() Triggers animation by setting s_frame_offset = 30
FrameinOutExec() Called each frame in the main loop; decrements s_frame_offset toward 0
getFrameOffset() Returns (s_frame_offset²) / 3 — quadratic ease-in (fast start, smooth settle)

At frame 0 the offset is 900/3 = 300 pixels, pushing UI elements far off-screen. It decays quadratically over 30 frames until it reaches 0, at which point all elements are in their final positions. The offset then stays at 0 for the rest of program execution.

The offset is applied to every major element's position, creating the convergence effect:

Element Offset Applied Effect
Upper BG (m_motion_bg.top) -1 × getFrameOffset() Slides in from above
Lower BG (m_motion_bg_down.top) +1 × getFrameOffset() Slides in from below
Game thumbnails THUMBNAIL_Y - getFrameOffset() Drop in from above
Thumbnail X positions -2×, -1×, +1×, +2× multipliers Fan in from left/right
Cursor, title text, guide icons +/- getFrameOffset() Converge to final position
Settings/Sort labels y + getFrameOffset() Slide in from below
Re-trigger points setFrameinOut() is called on first load, but also after exiting settings (if save data was initialized), after a frame type change, after a lineup switch, and when returning from a game — replaying the convergence animation each time.

Guide Button Icons

getFrameTypeGuideText() (utils.nut:2485) remaps button icon characters depending on the lineup and theme. The US lineup has its own fixed remapping that ignores the frame type. On the JP lineup, the frame type selects between two icon sets. The custom font uses Cyrillic characters as symbol codes for controller button glyphs:

Default Icon PC Engine (JP) CoreGrafx (JP) US Lineup
Ι (Iota) Ι (unchanged) Ж (Zhe) И (I)
Κ (Kappa) Κ (unchanged) Б (Be) Л (El)
Μ (Mu) Μ (unchanged) Г (Ge) Ц (Tse)
Λ (Lambda) Λ (unchanged) б (be) П (Pe)

Each character maps to a specific button glyph (I, II, SELECT, RUN etc.) in M2's custom icon font. The different Cyrillic codepoints map to visually distinct button styles matching each console's aesthetic.

Guide Text Color

The MenuModeGuide class (utils.nut:2545) can optionally tint guide text based on the frame type. When colorChange = true:

  • JP + PC Engine → blue text prefix: #{color,00000FF}
  • JP + CoreGrafx → no color change (default text color)
  • US lineup → no color change (frame type ignored)

Initial Language Selection

On first boot, the language selection screen (mode_title_select_settinglang.nut) auto-sets the frame type based on the chosen language. This only applies to the US/EU retail version (DEVID_US):

Language Frame Type Default Lineup
Japanese PC Engine (0) (unchanged)
English CoreGrafx (1) (unchanged)
French CoreGrafx (1) JP
Italian CoreGrafx (1) JP
German CoreGrafx (1) JP
Spanish CoreGrafx (1) JP

On the JP retail version (DEVID_JP), the language choice does not change the frame type — it stays PC Engine.

European languages set JP lineup On the US/EU retail version, choosing French, Italian, German, or Spanish not only sets the CoreGrafx frame but also switches the default lineup to JP (PC Engine games). This makes sense because the EU version was sold as "CoreGrafx Mini" and these languages were targeted at the European market.

Complete Propagation Flow

User selects frame type in settings | v set_74_frameType() → persisted to BACKUP_FLAGS | v Exit settings menu | +→ Compare frameTypeOld vs current | If changed AND lineup == JP: | | | +→ setFrameinOut() → triggers 30-frame bounce animation | +→ getBGMotionName() → returns "bg" or "bg_eu" | +→ Reload all BG layers with new chara: | m_motion_bg.chara = "bg" / "bg_eu" | m_motion_bg_down.chara = "bg" / "bg_eu" | m_motion_bg_back[].chara = "bg" / "bg_eu" | +→ getFrameTypeGuideText() → remap button icon glyphs +→ MenuModeGuide color → blue tint for PCE, default for CoreGrafx +→ WallpaperBG → uses same getBGMotionName() on next open
